# 下一关：自己再造一个训练任务

“训练各种动作”通常不是把所有按钮塞进一个 reward。更稳妥的做法是先让每个任务有清楚的成功条件，
分别学会，再决定是否做统一策略或运行时切换。

下一只最值得训练的是**踢球鸭**：仓库已经有球的尺寸、质量和左右脚摆放基线，成功指标也直观，直播时
比奖励曲线更容易看懂。先做单侧踢球，再镜像到另一侧；不要第一天就把走路、起身、踢球和前滚塞进
同一张网里互相抢 reward。

## 推荐顺序

| 任务 | 场景里要新增什么 | 最重要的成功指标 |
| --- | --- | --- |
| 粗糙地形行走 | height-field、台阶、坡面 | 不摔倒且跟得上速度 |
| 起身 | 仰躺/趴倒随机出生 | 在时间内回到稳定站姿 |
| 踢球 | 70 mm、15 g 球和左右脚目标 | 球向目标方向移动且鸭子不倒 |
| 低头碰地 | 嘴尖 contact/site 目标 | 碰到地面后能重新站稳 |
| 坐下/起身 | 二值姿态命令 | 两个方向都能温和完成 |

## 从现有任务复制哪几块

原生任务在 `source/microduck_isaac_lab/microduck_isaac_lab/tasks/velocity/`。新增任务时保留公共模型和
61 维契约，替换真正与任务相关的部分：

1. `SceneCfg`：球、障碍、地形或目标；
2. `EventsCfg`：出生姿态、物体位置、扰动和随机化；
3. `RewardsCfg`：一个主任务奖励，加少量安全/平滑约束；
4. `TerminationsCfg`：成功、摔倒、超时；
5. `CurriculumCfg`：先学会动作，再逐步增加难度和动作税；
6. `agents/`：通常先复用同一个 PPO 配置，确认环境问题后再调网络。

## 别把 5 轮 smoke 当训练结果

一个新任务至少需要三种检查：

- **契约检查**：观测是 61 维、动作是 14 维、关节顺序没变；
- **短训练检查**：多环境能 reset、奖励 finite、PPO 能更新和保存；
- **行为检查**：回放 checkpoint，动作确实完成，不能只看总 reward 上升。

当一个任务稳定后，再考虑共享 actor、skill id、蒸馏或运行时多策略切换。现有
[多动作游乐场](./playground)已经演示了最后一种：每个动作一张网，按状态安全切换。
