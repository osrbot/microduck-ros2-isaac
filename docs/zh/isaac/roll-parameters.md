# 参数和奖励怎么设计

这一页回答两个问题：这些数字从哪里来？动作不理想时先动哪一个？
先记住顺序：**模型接口和初始化正确 → 奖励与目标一致 → 短训练看行为 → 再调优化器**。
如果一出生就在地板里，先换学习率通常解决不了问题。

## 1. 先找到真正生效的配置

| 文件或入口 | 负责什么 |
| --- | --- |
| `tasks/velocity/velocity_env_cfg.py` | 模型、关节动作、61 维观测、仿真步长 |
| `tasks/velocity/continuous_roll_env_cfg.py` | 翻滚命令接口、基础终止条件、早期配置 |
| `tasks/velocity/full_roll_env_cfg.py` | 本例的完整翻转奖励、重置修正和方向优化 |
| `tasks/velocity/agents/rsl_rl_ppo_cfg.py` | PPO 网络和优化参数基线 |
| `scripts/train_isaac_velocity.py` | 解析选项、覆盖部分参数、热启动与续训 |
| `roll_metrics.py` | 独立的姿态进度和完整翻转计数 |

前四个文件和 `roll_metrics.py` 位于 `source/microduck_isaac_lab/microduck_isaac_lab/` 下。
带 `--full-roll-v2` 时，训练脚本还会覆盖 `clip_actions=None`、`save_interval=100`、`learning_rate=1e-4`、`desired_kl=0.005`。
因此，**每次运行保存的 `params/env.yaml` 和 `params/agent.yaml` 才是这次实际配置的快照**。
如果要修改以上四项，检查脚本里的覆盖，避免只改基类却没有生效。

想调整方向奖励时，打开 `full_roll_env_cfg.py` 的 `StraightFullRollRewardsCfg`，修改对应 `weight`，再通过 `--straight-roll` 启用。
每次新建 run，保存配置差异，回放后再决定保留。最初的检查点和参数快照留作回退基线。

## 2. 接口参数：先保持一致

### 为什么是 61 维观测、14 维动作？

它们来自已有策略的输入输出约定。61 维观测依次为：

```text
机身角速度 3 + 重力投影 3
+ 关节相对位置 14 + 关节相对速度 14
+ 上一步动作 14 + 命令 13 = 61
```

13 个命令包含速度 3、头部 4、身体 6；在这个翻滚任务里全部置零，与原翻滚策略的输入一致。
这版策略没有目标方向指令，方向约束使用固定的世界坐标轴。

14 维动作是按约定关节顺序排列的位置偏移。`scale=1.0`、`use_default_offset=True`，因此关节目标为：

```text
目标关节位置 = 默认关节位置 + 策略动作
```

动作在这里对应弧度偏移。观测顺序、关节顺序、单位、默认姿态或归一化统计一旦变化，旧网络可能输出不合适的动作。
应同时检查这些接口，不只核对数组长度。

### 动作截断和 PPO clip 是两回事

- `clip_actions=1.0` 会在控制接口把动作压到 `[-1, 1]`。
- `algorithm.clip_param=0.16` 是 PPO 更新目标中的策略概率比剪切参数，不限制电机动作幅度。

初始诊断中，原翻滚策略约 15.9% 的原始动作超过 `±1`，最大绝对值约 3.04。
因此完整翻滚配置恢复了原策略所需的输出范围。去掉截断后原策略仍没有完成整圈，后续还需要奖励和初始化修正。
执行器力矩、转速和关节限制仍按模型配置保留；新硬件或新动作接口应重新核对限幅与安全约束。

### 热启动具体继承了什么？

`warm_start_actor_from_onnx()` 拷贝 Actor 的 MLP 权重、偏置和观测归一化统计；探索噪声由 runner 配置初始化。
Critic 的价值估计继续通过 PPO 学习。已有动作知识帮助探索从翻滚附近开始，因此本次耗时不能作为随机权重训练的预算。
更换源 ONNX 时先核对名称、层尺寸、归一化数据和 SHA-256。

## 3. 时间、采样量与初始高度

| 参数 | 本例值与来源 | 怎么理解和调整 |
| --- | --- | --- |
| 物理步长 | `0.005 s`，继承模型仿真基线 | 每秒 200 个物理步；更改后需要重查接触和控制行为 |
| 控制 decimation | `4`，继承基线 | 每 4 个物理步更新一次动作，即 `0.02 s / 50 Hz` |
| 并行环境 | 短测试 64，正式实验 1024 | 先满足显存；增加环境数也增加每轮数据量 |
| 每环境 rollout | `32` 步，继承翻滚 PPO 配置 | 1024 × 32 = 32,768 条 transition / 更新；每环境采样 0.64 秒 |
| 训练 episode | `12 s`，本次完整翻滚配置 | 最长 600 个控制步；终止条件触发时会更早重置 |
| 回放长度 | `2500` 步，即 50 s | 用更长回放观察续翻；PLAY 的 episode 上限为 60 s |
| 检查点间隔 | `100` 次更新，本次调整 | 更早得到可回放候选；磁盘开销与诊断频率取舍 |

iteration 是一次采样和学习更新；环境步数、仿真时间、墙钟时间是不同量。
续训的 `--max-iterations` 表示追加更新次数，保存文件的数字是运行标签。标签 600 不等于整个实验只训练过 600 次。

### `0.125 m` 怎么得到？

USD 内部的 trunk 具有 `0.12 m` 偏移，配置的初始根位置是 `0.005 m`。场景初次组合出来的位置与 reset API 使用的位置不一致。
本次在 reset 的 z 偏移补上 `0.12 m`：

```text
重置根高度 = 0.005 m + 0.12 m = 0.125 m
```

这是当前模型的坐标修正。换模型时重新检查 authored transform、根位置、脚底接触和 `initial_root_height_m`，不直接沿用这个高度。
训练出生 pitch 为 `±0.05 rad`，关节位置缩放为 `0.995～1.005`，速度初值为零。

## 4. 奖励先回答“怎样才算往前翻了”

对每个环境，用机身坐标中的重力投影 `g` 得到俯仰相位：

```text
phase = atan2(g.x, -g.z)
delta = 把相邻 phase 的差映射到 [-π, π)
net = net + delta
peak = max(旧 peak, net)
new_progress = peak - 旧 peak
```

往回转会减小 `net`。再次走过已经到达的角度时没有新进度；只有跨过旧最高点才获得进度奖励。
`peak` 每跨过一个 `2π`，再记录一圈完整翻转。

例如“向前 120°、向后 120°”重复十次，正向角速度积分会不断增加；净翻转进度仍回到起点，完整圈数保持零。
对应的曲线见[调试页](./roll-debugging#diagnosis)。

### 权重 8 和 6，要连同 dt 一起看

Isaac Lab 的奖励管理器按 `weight × term × dt` 累加各项；说明见 [RewardManager 文档](https://isaac-sim.github.io/IsaacLab/main/source/api/lab/isaaclab.managers.html#isaaclab.managers.RewardManager)。
本例把速率项与离散事件项分别处理：

```text
进度项 term = min(new_progress / dt, 6 rad/s) / (2π)
进度项得分 = 8 × term × dt

整圈项 term = 本步新完成圈数 / dt
整圈项得分 = 6 × 本步新完成圈数
```

没有触及速率上限时，每推进一个全新的整圈，进度累计约得 8 分，再获得 6 分整圈奖励。
6 rad/s 是限制单步进度得分的经验上限，避免瞬间极快的角度变化获得过高分数；它不限制机器人的物理角速度。

8 和 6 是本次选用的经验权重，分别提供持续引导和完成奖励，并未做全范围最优搜索。
太强调进度可能得到猛烈动作；只留稀疏整圈奖励又可能让探索困难。调整后同时看圈数、动作平滑和重置，保留回退模型。

### 各约束控制什么？

下面是方向优化阶段的值；平方项会随误差幅度快速增大，因此不同项的权重不能脱离单位直接比较。

| 奖励项 | 权重 | 被约束的量 | 调整后重点看 |
| --- | --- | --- | --- |
| 反向俯仰 | `-0.05` | 反向 pitch 角速度，rad/s | 回摆是否减少，起翻是否受阻 |
| 侧倒倾向 | `-0.5` | 重力投影 `g_y²`，无量纲 | 是否向侧面倒，正常倒置能否继续 |
| 滚动轴对齐 | `-3` | `1 - 世界坐标下机身Y轴的Y分量` | 平面方向是否更稳定 |
| 横向速度 | `-3`，前两轮为 `-0.2` | 世界坐标 `v_y²`，m²/s² | 横向偏移是否下降，圈数是否退步 |
| 偏轴转动 | `-0.03`，前两轮为 `-0.01` | 机身 `ω_x² + ω_z²`，rad²/s² | 侧滚、偏转与正常前翻是否平衡 |
| 动作变化 | `-0.02` | 相邻关节动作差的平方和 | 是否抖动，惩罚过强时是否不愿起翻 |
| 软关节越界 | `-0.1` | 超出软限位的关节位置距离 | 越界是否增加，动作是否被过度压制 |
| 关节力矩 | `-1e-5` | 力矩平方和，N²·m² | 是否出现长期高力矩接触 |

前翻围绕机身 Y 轴进行。纯俯仰转动不会改变这根轴的方向，所以对齐世界 Y 轴可以约束翻滚平面，同时允许身体翻到倒置。
若错误地要求机身 Z 轴始终朝上，就会直接与完整翻滚冲突。

完整翻滚配置移除了早期的目标线速度、静止也能获得的高度带奖励，以及自动提速 curriculum。
先让完整动作可学，再单独优化方向。本次没有同时增加力矩上限、改变重力或施加额外助推力。

## 5. PPO 参数：先稳住已有动作

这些数值来自 `MicroDuckContinuousRollPPORunnerCfg` 和 `--full-roll-v2` 的覆盖，网络结构与多数超参数沿用已有翻滚基线。
PPO 的基本思路可参考[原论文](https://arxiv.org/abs/1707.06347)；下面的取值是本项目配置，论文不会直接给出这只机器人的最佳数值。

| 参数 | 本例值 | 作用与调整判断 |
| --- | --- | --- |
| Actor / Critic | `512 / 256 / 128`，ELU | 兼容原 Actor 结构；热启动时不先改网络尺寸 |
| 初始学习率 | `1e-4`；早期翻滚配置 `1.5e-4` | 降低每次更新幅度；动作快速退化时结合 KL 检查 |
| schedule / desired KL | `adaptive / 0.005`；早期 KL 为 `0.008` | 用策略变化量调节学习率；目标更小一般更保守 |
| PPO clip | `0.16` | 控制更新目标的概率比剪切范围，与动作截断不同 |
| gamma / GAE lambda | `0.995 / 0.95` | 未来回报和优势估计的基线设置，本轮未单独搜索 |
| entropy coefficient | `0.003` | 保留探索；过高可能破坏已有动作，过低可能停在局部行为 |
| 初始动作标准差 | `0.28` | 从已有 Actor 附近探索；与 entropy 系数是不同参数 |
| epochs / mini-batches | `5 / 8` | 每段采样重复学习 5 遍；1024 环境时每批约 4096 条样本 |
| max grad norm | `0.8` | 限制梯度范数；不能代替观测和奖励的 finite 检查 |
| value loss coefficient | `1.0` | Critic 学习权重，沿用基线 |
| 训练 seed | `108` | 固定本次训练起点；换 seed 后重新回放验收 |

自适应调度会改变学习率；从 `.pt` 续训还会加载优化器等状态。`1e-4` 是配置初值，实际过程应看运行日志。
学习率、KL 和奖励在阶段切换中可能一起变化，因此本案例属于工程调试记录，不是单因素消融实验。

## 6. 为什么先关掉大范围随机化？

本例关闭观测噪声、质量随机化、摩擦随机化和定时推扰，只保留很小的出生姿态及关节扰动。
这样更容易区分：动作目标本身难以学习，还是随机环境太难。

连续动作稳定后，再一次增加一组随机化，并复用同一批回放指标。扩大摩擦、姿态、质量或外力范围属于新的实验，尚不在本次结果中。
不要一边降低随机化一边提高学习率、换奖励和改网络，然后试图从一条总奖励曲线解释所有变化。

## 7. 验收阈值的来历也要清楚

| 阈值 | 用途 | 来源与取舍 |
| --- | --- | --- |
| `abs(g_y) < 0.55` | 避免接近侧躺时俯仰投影失去可靠含义 | 工程有效区间，换动作需重新检查 |
| 单步相位差 `< 1.2 rad` | 排除突变造成的相位拼接 | 按当前 50 Hz 采样设的连续性防护 |
| 反向退回 `> π/2` | 打断当前连续翻滚链 | 允许小幅回摆，但明显反转另起一段 |
| 至少连续 3 圈且零重置 | 最基本的连续动作检查 | 本次定义的阶段目标 |
| 最大整圈间隔 `≤ 3 s` | 排除翻几圈后长时间停住 | 工程验收线，包含起步和结尾 |

圈数计数器保留历史最长连续链；长时间停住要靠时间间隔条件一起检查。
单元测试覆盖摆动、反向、重置、侧倒和多环境独立计数。阈值改变后要重跑测试，再看逐帧姿态和视频。
